## 让阅读舒服，也让远程操作有确定感

这个 App 会承载长回答、执行进展、需要用户决定的问题，以及可领取的成果。因此，设计同时围绕两件事展开：连续阅读时足够安静，需要采取行动时足够明确。

浅色选择暖纸，减少大面积冷白的生硬感；深色选择带少量青色的石墨，用不同明度组织层次。玉青贯穿两种外观，承担主操作、链接和选中态。使用者可以跟随系统，也可以固定选择暖纸或石墨。

## 颜色首先表达用途

颜色集中定义在 [DesignSystem.swift](../ios/XVIS/DesignSystem.swift)。下面是普通对比度下的当前值；高对比度模式另有更清晰的文本、边框和强调色变体。

| 语义 | 暖纸 | 石墨 | 用途 |
| --- | --- | --- | --- |
| 背景 | `#FAF7F1` | `#0D1213` | 页面底色 |
| 表面 | `#FFFDF8` | `#151D1F` | 内容卡片与分层 |
| 抬升表面 | `#FFFDF8` | `#1E2A2C` | 浮层和较突出的控件 |
| 正文 | `#2F2925` | `#E8EFED` | 长文与主要信息 |
| 次要文字 | `#746559` | `#A1B1AD` | 时间、说明、辅助信息 |
| 玉青 | `#176F66` | `#72D0BD` | 主操作、链接、选中态 |
| 强调底上的文字 | `#FFFFFF` | `#092720` | 主要按钮内容 |
| 柔和强调底 | `#EAF0E8` | `#1A302D` | 轻量选中与强调区域 |
| 边框 | `#E4DED2` | `#2E3D3E` | 相邻层级的边界 |
| 成功 | `#24764A` | `#83D29E` | 已完成等正向状态 |
| 警示 | `#976217` | `#E8B567` | 待处理、需要注意 |
| 错误 | `#B74642` | `#F49891` | 失败与不可用 |

深浅模式分别定义颜色，文本和背景之间保持层次。状态还配有文字与图标，避免仅靠颜色表达成功、失败或等待。当前实现包含无障碍适配，但仓库没有宣称已经取得完整的无障碍认证。

## 排版与材质

正文使用系统字体与语义字号，支持 Dynamic Type。当前正文额外行间距为 5 pt；这与固定的“1.55 倍行高”不是同一个排版参数。标题、段落、列表、引用和代码块各自保留层级。表格可以横向阅读，避免为了塞进手机而把内容缩小成难以辨认的字。

主要触控区域按至少 44 pt 的方向设计。大字号下优先换行，重要动作保留可读标签。长回答分为稳定的 Markdown 区块和正在追加的尾部，减少流式更新反复打乱整篇排版的机会。

原生玻璃用于浮动控件和导航层；正文仍保留稳定、可读的表面。iOS 26+ 使用系统玻璃 API，旧系统提供主题表面兼容路径。开启减少透明度或提高对比度时，控件使用更明确的实色表面。最低部署目标为 iOS 17，构建需要支持相关新 API 的 SDK。

## 动效应解释变化

| 当前实现 | 参数或行为 | 作用 |
| --- | --- | --- |
| 按钮按压 | 缩放至 `0.97`，约 `0.10 s` ease-out | 确认手指已经按下 |
| 部分界面状态切换 | 约 `0.18 s` | 连接状态之间的变化 |
| 回答首次出现 | 约 `0.18 s` 的轻量过渡 | 让新内容进入阅读区 |
| 复制反馈 | 约 `0.16 s` | 让动作有可见回执 |
| 触觉反馈 | 关键轻操作使用系统反馈，可关闭 | 补充视觉回执 |

系统“减少动态效果”会影响相关动画路径。触觉效果仍需要真机主观检验，模拟器不能证明它在手中的感受。设计没有用持续闪动代替真实进度；等待和执行以实际任务状态及事件为依据。具体参数以 [DesignSystem.swift](../ios/XVIS/DesignSystem.swift) 和 [ConversationViews.swift](../ios/XVIS/ConversationViews.swift) 为准。

## 细节来自工作连续性

视觉升级也包括状态管理。输入稿在离开页面后仍应存在；用户正在阅读旧内容时，新内容不应轻易抢走位置；前往应用内网页再返回时，应能回到阅读区域。连续会话先提供近期 20 轮，再按需加载更早记录。

“待我处理”与“未查看结果”承担不同任务：前者需要回答或批准，后者表示有成果尚未阅读。批准卡显示具体工具和参数；提交答复后还要等待执行端确认，避免一个按钮动画让人误以为动作已经执行完成。

文件也有自己的交付状态。任务已经完成，附件仍可能需要重新下载；只有领取后的内容通过大小与 SHA-256 检查，才进入可用缓存。完整性检查证明传输一致，内容质量仍需审阅。

## 设计灵感怎样落到项目里

- [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 和 [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：采用系统材质、平台反馈与辅助设置，保证原生交互连贯。
- [Linear 的界面重设计记录](https://linear.app/now/how-we-redesigned-the-linear-ui)：参考层级、对齐和密度控制；XVIS 将关注点放在手机阅读和少量关键动作上。
- [Things 的 OS 26 设计更新](https://culturedcode.com/things/blog/2025/09/things-for-os-26/)：参考成熟原生工具对新系统语言的吸收方式，保持内容优先。
- [DeepSeek Harness Mobile](https://github.com/yukiykchen/deepseek-harness-mobile)：启发移动端接住执行中的问答、批准与持续控制。本项目继续使用 SwiftUI 与自有 Node–Hub 协议。

研究阶段的建议经过筛选后才进入实现。当前参数、截图与开发进展共同说明实际交付；仍在规划的语音和分享入口见 [路线图](roadmap.md)。
